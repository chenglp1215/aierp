## Context

销售订单是 ERP 核心业务模块，当前使用 MySQL + Tortoise ORM 存储。采购单下推销售单时，已有 `source_sale_order_id` 和 `source_sale_order_no` 字段关联，但缺少成本回填机制。

当前架构：
- 销售订单主表 `sales_orders`，明细表 `sales_order_items`
- 采购订单主表 `purchase_orders`，明细表 `purchase_order_items`
- 采购单通过 `source_sale_order_no` 关联销售单
- 采购单已有 `freight_amt` 字段支持运费录入

## Goals / Non-Goals

**Goals:**
- 实现销售单成本明细独立管理，支持采购成本、运费、调货费等多种成本类型
- 成本明细与采购单关联，采购单审核通过时自动创建（采购成本+运费）
- 列表接口实时计算成本和利润（含税金额）
- 前端列表支持展开行查看商品明细
- 前端列表支持行选中批量操作

**Non-Goals:**
- 不与应收款模块（MongoDB）联动，财务状态独立维护
- 不实现成本明细的前端管理界面（仅后台 API）
- 快递平台接口对接自动获取运费（预留待后续实现）

## Decisions

### 1. 成本明细模型设计

**决策**: 新增独立模型 `SalesOrderCostItem`，1:N 关联销售订单

**理由**:
- 成本来源多样（采购、运费、调货），独立模型更灵活
- 支持手动添加额外成本（如运费）
- 便于追溯成本来源（关联采购单号）

**备选方案**:
- 方案A: 在销售单主表新增 `cost_amt` 字段 → 不支持多来源成本记录
- 方案B: 在采购单明细记录成本 → 无法添加非采购成本

### 2. 成本计算时机

**决策**: 列表查询时实时计算，不存储到主表

**理由**:
- 成本明细可能随时变更（如新增运费）
- 实时计算保证数据一致性
- 使用 SQL 聚合，性能影响可控

### 3. 利润计算公式

**决策**: `profit_amt = total_tax_amt - cost_amt`（含税金额计算）

**理由**:
- 用户确认使用含税金额计算利润
- 成本明细的 `amount` 存储含税金额
- 与销售单含税销售额对应

### 4. 采购成本触发时机

**决策**: 采购单审核通过时创建成本明细

**理由**:
- 审核通过代表采购确认，成本生效
- 同时创建采购成本（含税金额）和运费成本（如有）
- 避免采购中途创建后又取消的冗余数据

**备选方案**:
- 方案A: 下推采购时立即创建 → 采购可能取消，成本无效
- 方案B: 付款完成时创建 → 付款与成本确认无直接关联

### 5. 前端展开行实现

**决策**: 使用表格行内嵌套子表格方式

**理由**:
- Vue 3 Composition API 支持良好
- 不依赖第三方组件库（如 vxe-table 的展开行）
- 样式可控，与现有 UI 风格一致

## Risks / Trade-offs

### [成本重复创建风险]
采购单多次审核通过可能重复创建成本明细
→ **缓解**: 创建前检查 `purchase_order_id` + `cost_type` 是否已存在成本明细

### [成本金额变更同步]
采购单金额变更后，已创建的成本明细需同步更新
→ **缓解**: 采购单更新时，同步更新关联成本明细的 `amount`

### [列表查询性能]
实时计算成本需额外查询成本明细表
→ **缓解**: 使用 SQL 聚合 `SUM(amount)`，单次查询完成

### [财务状态维护]
财务状态独立维护，可能与实际付款状态不一致
→ **缓解**: 提供手动更新财务状态的 API，后续可对接财务模块

## Migration Plan

### Phase 1: 数据库迁移
1. 创建 `sales_order_cost_items` 表
2. `sales_orders` 表新增 `finance_status` 字段
3. `sales_order_items` 表新增 `exchange_qty`、`supplement_qty` 字段

### Phase 2: 后端服务
1. 新增 `SalesOrderCostItem` 模型
2. 销售单服务增强列表接口
3. 采购单服务审核通过时创建成本明细
4. 新增成本明细 API 路由

### Phase 3: 前端改造
1. 列表表格列配置调整
2. 展开行功能实现
3. 选中行功能实现

### 回滚策略
- 数据库字段可设置默认值，不影响现有数据
- 新增表可删除，不影响原有业务
- 前端改造可独立回滚
