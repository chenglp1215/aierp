## Context

项目当前使用 Tortoise ORM 连接 MySQL 数据库，配置通过 `backend/config/settings.py` 管理，使用 Pydantic Settings 从 `.env` 文件读取环境变量。数据库初始化流程包括：

1. 服务启动时通过 `init_mysql()` 建立连接并自动生成表结构
2. 运行 `init_db_mysql.py` 脚本初始化默认数据（权限、角色、管理员账号）

当前配置默认指向 `localhost:3306`，需要更新为远程测试数据库地址。

## Goals / Non-Goals

**Goals:**
- 配置本地开发环境连接到远程 MySQL 测试数据库
- 确保服务启动时能够自动创建/更新数据库表结构
- 确保数据库初始化脚本能够正常运行

**Non-Goals:**
- 不涉及数据库迁移工具（如 Aerich）的配置
- 不修改现有数据库模型结构
- 不涉及生产环境配置

## Decisions

### 1. 配置方式：使用 .env 文件

**决定**: 创建 `backend/.env` 文件存储本地开发配置

**理由**:
- 符合项目现有的 Pydantic Settings 配置模式
- `.env` 文件已在 `.gitignore` 中，不会提交敏感信息
- 便于不同开发者使用不同的本地配置

**替代方案**:
- 直接修改 `settings.py` 默认值：不推荐，会影响其他开发者
- 使用 `.env.local`：可行，但项目已有 `.env.example`，保持一致性更好

### 2. 数据库表初始化策略

**决定**: 保持现有的 `generate_schemas=True` 自动生成策略

**理由**:
- Tortoise ORM 的 `generate_schemas=True` 会在启动时自动创建不存在的表
- 适合开发环境，简化开发流程
- 现有模型定义清晰，自动生成的表结构符合预期

**注意事项**:
- 该策略只会创建新表，不会自动修改现有表结构
- 后续如需表结构变更，需要手动处理或引入迁移工具

### 3. 初始化数据执行时机

**决定**: 初始化数据脚本保持手动执行，不集成到服务启动流程

**理由**:
- 初始化数据只需执行一次
- 自动执行可能导致重复插入或数据冲突
- 现有脚本已实现幂等性（检查已存在则跳过）

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 远程数据库连接不稳定 | 设置合理的连接超时时间（10秒），服务启动时验证连接 |
| 表结构变更需要手动处理 | 后续可考虑引入 Aerich 迁移工具 |
| 密码明文存储在 .env | .env 已在 .gitignore 中，仅本地开发使用 |
