## Context

当前项目有两个相关需求：
1. 数据库初始化脚本 `init_db_sync.py` 是简化版，只创建了超级管理员角色，缺少原有的仓库管理员、采购组、普通用户三个固定角色
2. 前端 `DashboardHeader.vue` 组件有设置按钮但无实际功能

用户管理相关代码已存在：
- 后端：`PUT /api/v1/users/{user_id}` 接口支持更新用户信息
- 前端：`UserManagement.vue` 已有用户编辑弹窗的实现

## Goals / Non-Goals

**Goals:**
- 恢复数据库初始化脚本中的 4 个固定角色
- 实现用户设置弹窗，允许用户编辑自己的邮箱和密码

**Non-Goals:**
- 不修改用户管理模块的核心功能
- 不新增后端 API

## Decisions

### 1. 数据库初始化脚本修改方式

**决定**: 直接修改 `init_db_sync.py`，添加三个缺失角色的初始化函数

**理由**:
- 保持脚本结构一致
- 原始 `init_db_mysql.py` 已有完整实现，可直接参考移植
- 幂等性设计：检查角色是否存在，存在则跳过

### 2. 用户设置弹窗组件设计

**决定**: 创建独立的 `UserSettingsDialog.vue` 组件

**理由**:
- 组件职责单一，便于维护
- 可复用 `UserManagement.vue` 中的表单样式
- 通过 props 控制显示/隐藏，emit 通知父组件

**替代方案**:
- 在 `DashboardHeader.vue` 中内联实现：代码臃肿，不利于维护
- 复用 `UserManagement.vue` 的编辑弹窗：需要大量修改，耦合度高

### 3. API 调用方式

**决定**: 复用现有的 `authApi.updateUser` 接口

**理由**:
- 现有接口已支持更新邮箱和密码
- 通过 localStorage 获取当前用户 ID
- 无需新增后端接口

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 初始化脚本执行时角色已存在 | 幂等性检查，已存在则跳过 |
| 用户修改密码后需要重新登录 | 保存成功后提示用户，可选择自动登出 |
