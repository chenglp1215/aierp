### 各层职责

| 层 | 目录 | 职责 |
|----|------|------|
| **路由层** | `routers/` | 接收请求、参数解析、调用服务、返回响应 |
| **服务层** | `services/` | 业务逻辑处理、数据组装、业务规则校验 |
| **模型层** | `models/` | Pydantic 数据结构定义、字段验证规则 |
| **校验层** | `validators/` | 自定义业务校验逻辑 |

## 2. 代码风格

### 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件 | 小写下划线 | `sales_order_service.py` |
| 类 | 大驼峰 | `SalesOrderService` |
| 函数 | 小写下划线 | `get_order_by_no` |
| 常量 | 全大写下划线 | `BLOCK_STATUS_CHOICES` |
| MongoDB 集合 | 小写下划线 | `sales_orders`、`product_categories` |
| 路由前缀 | 小写连字符 | `/sales-orders`、`/procurement-orders` |

### 函数复杂度

- 单函数不超过 20 条语句
- 超过需拆分为子函数
- 使用中文注释说明复杂逻辑的原因

### 代码格式化

- Black 格式化代码
- isort 管理导入顺序
- flake8 检查代码质量

## 3. 接口规范

### 路由架构

- 所有 API 路径前缀: `/api/v1`
- 认证方式: Bearer Token (JWT)
- HTTP 状态码: 仅使用 200（成功）、401（未认证）、5XX（服务器错误）
- 业务错误通过响应体中的 `status: "error"` 表示

### 统一响应格式

#### 成功响应（列表）

```json
{
  "status": "success",
  "message": "操作成功",
  "result": {
    "total": 100,
    "page": 1,
    "page_size": 20,
    "items": [...]
  }
}
```

#### 成功响应（详情）

```json
{
  "status": "success",
  "message": "操作成功",
  "result": { ... }
}
```

#### 错误响应

```json
{
  "status": "error",
  "message": "错误描述信息",
  "result": null
}
```

#### 校验错误响应

```json
{
  "status": "error",
  "message": "参数验证失败",
  "validation_errors": [
    { "field": "name", "message": "名称不能为空" }
  ]
}
```

### 编写示例

#### 路由编写模式

```python
from fastapi import APIRouter
from app.decorators import handle_result
from services.xxx_service import XxxService

router = APIRouter(prefix="/api/v1/xxx", tags=["xxx"])

@router.get("/")
@handle_result
async def list_xxx(page: int = 1, page_size: int = 20):
    """列表查询"""
    service = XxxService()
    return await service.list(page=page, page_size=page_size)

@router.get("/{id}")
@handle_result
async def get_xxx(id: str):
    """详情查询"""
    service = XxxService()
    return await service.get_by_id(id)

@router.post("/")
@handle_result
async def create_xxx(data: dict):
    """创建"""
    service = XxxService()
    return await service.create(data)

@router.put("/{id}")
@handle_result
async def update_xxx(id: str, data: dict):
    """更新"""
    service = XxxService()
    return await service.update(id, data)

@router.delete("/{id}")
@handle_result
async def delete_xxx(id: str):
    """删除"""
    service = XxxService()
    return await service.delete(id)
```

#### 使用 handle_result 装饰器

`handle_result` 装饰器统一处理服务层返回值和异常：

- 返回 tuple `(success: bool, result, message)` 格式
- 异常时自动捕获并返回标准错误格式
- 避免在路由层手动构造响应

```python
# 服务层返回格式
return True, result_data, "操作成功"       # 成功
return False, None, "数据不存在"           # 失败
```

#### 参数校验模式

使用 validators 目录下的校验器进行业务校验：

```python
from validators.xxx_validator import validate_create_xxx

@router.post("/")
@handle_result
async def create_xxx(data: dict):
    # 校验参数
    errors = validate_create_xxx(data)
    if errors:
        return False, None, "参数校验失败", errors

    service = XxxService()
    return await service.create(data)
```

### HTTP 状态码规范

| 状态码 | 说明 | 使用场景 |
|--------|------|---------|
| 200 | 请求成功 | 所有成功请求（含业务错误） |
| 401 | 未认证 | Token 缺失或过期 |
| 5XX | 服务器错误 | 未捕获的异常 |

## 4. 服务实现风格

### BaseService 基类

所有业务服务继承 `BaseService`，提供统一的 MongoDB CRUD 操作：

```python
from services.base_service import BaseService

class XxxService(BaseService):
    def __init__(self):
        super().__init__("collection_name")  # MongoDB 集合名
```

#### BaseService 提供的方法

| 方法 | 说明 |
|------|------|
| `get_by_id(id)` | 按 ID 查询单条 |
| `list(filters, page, page_size)` | 分页列表查询 |
| `create(data)` | 创建记录 |
| `update(id, data)` | 更新记录（支持 `$` 开头操作符透传） |
| `delete(id)` | 删除记录 |
| `find_many(filters, limit)` | 查询多条 |

#### 服务层编写示例

```python
from services.base_service import BaseService
from models.xxx import XxxCreate

class XxxService(BaseService):
    def __init__(self):
        super().__init__("xxx_collection")

    async def create_xxx(self, data: dict):
        """创建业务记录"""
        # 业务逻辑处理
        result = await self.create(data)
        if not result:
            return False, None, "创建失败"
        return True, result, "创建成功"

    async def get_xxx_list(self, page: int = 1, page_size: int = 20):
        """查询列表"""
        filters = {}
        result = await self.list(filters, page, page_size)
        return True, result, "查询成功"
```

### 数据模型编写模式

```python
from pydantic import BaseModel, Field
from typing import Optional
from datetime import datetime

class XxxBase(BaseModel):
    """基础字段"""
    name: str = Field(..., description="名称")
    status: str = Field(default="active", description="状态")

class XxxCreate(XxxBase):
    """创建请求"""
    pass

class XxxUpdate(BaseModel):
    """更新请求"""
    name: Optional[str] = None
    status: Optional[str] = None

class XxxResponse(XxxBase):
    """响应"""
    id: str
    created_at: datetime
    updated_at: datetime
```

### 校验器编写模式

校验器使用 **dict 配置 + `validate()` 函数**模式，定义在 `validators/` 目录下：

```python
# validators/xxx_validator.py

# ============ XXX 验证配置 ============

XXX_CREATE_CONFIG = {
    'name': {
        'required': True,
        'min_length': 1,
        'max_length': 200,
        'required_msg': '名称为必填'
    },
    'status': {
        'required': True,
        'enum': ['active', 'inactive'],
        'required_msg': '状态为必填'
    },
    'contact_info': {
        'fields': {  # 嵌套对象验证
            'phone': {
                'pattern': r'^1[3-9]\d{9}$',
                'msg': '手机号格式不正确'
            }
        }
    },
    'items': {
        'items': {  # 列表项验证
            'product_id': {'required': True, 'required_msg': '商品ID为必填'},
            'qty': {'required': True, 'type': int, 'min': 1, 'required_msg': '数量为必填'}
        }
    },
    '__conditional__': [  # 条件必填
        {
            'depends_on': 'status',
            'required_value': 'active',
            'field': 'reason',
            'message': '状态为启用时，原因不能为空'
        }
    ]
}

XXX_UPDATE_CONFIG = {
    'name': {
        'min_length': 1,
        'max_length': 200,
    },
    'status': {
        'enum': ['active', 'inactive'],
    }
}
```

#### 配置规则说明

| 规则 | 说明 | 示例 |
|------|------|------|
| `required` | 是否必填 | `True` / `False` |
| `required_msg` | 必填错误提示 | `'名称为必填'` |
| `type` | 类型检查 | `int`、`(int, float)` |
| `min_length` | 最小长度（字符串/列表） | `1` |
| `max_length` | 最大长度（字符串/列表） | `200` |
| `min` | 最小值（数字） | `0` |
| `max` | 最大值（数字） | `100` |
| `enum` | 枚举值 | `['active', 'inactive']` |
| `pattern` | 正则匹配 | `r'^1[3-9]\d{9}$'` |
| `msg` | pattern 匹配失败的提示 | `'格式不正确'` |
| `fields` | 嵌套对象验证 | `{'phone': {...}}` |
| `items` | 列表项验证 | `{'product_id': {...}}` |
| `__conditional__` | 条件必填 | 见上方示例 |

#### 在路由中使用

```python
from validators.base_validator import validate
from validators.xxx_validator import XXX_CREATE_CONFIG

@router.post("/")
@handle_result
async def create_xxx(data: dict):
    is_valid, errors = validate(data, XXX_CREATE_CONFIG)
    if not is_valid:
        return False, None, "参数校验失败", errors

    service = XxxService()
    return await service.create(data)
```

## 5. 模块拆分与解耦

### 标准模块文件结构

每个业务模块应包含以下文件（按需选用）：

```
模块名/
├── models/模块名.py              # 数据模型（Pydantic）
├── services/模块名_service.py    # 业务逻辑
├── validators/模块名_validator.py # 数据校验
└── routers/模块名.py             # API 路由
```

### 各层解耦原则

| 规则 | 说明 |
|------|------|
| 路由层不写业务逻辑 | 仅做参数解析和调用服务 |
| 服务层不依赖路由 | 通过返回 tuple 通信 |
| 模型层不做业务校验 | 仅定义数据结构 |
| 校验器不依赖服务 | 纯函数，接收 dict 返回 errors |

### 共享模块

`models/common.py` 存放跨模块共享的定义：

- 枚举类型（SettleType、ShippingMethod、OrderStatus 等）
- 工具函数（parse_datetime 等）
- 通用数据结构

### 模块间依赖规则

- 模块间通过服务层调用，不直接跨模块访问数据库
- 共享数据通过 `models/common.py` 中的枚举和工具函数
- 禁止循环依赖
